# Using xfig's sources (decided 2026-10-14)

Read this before porting or reviewing xfig/fig2dev code (linked from `CLAUDE.md`).

- xfig and fig2dev are under the xfig licence (SPDX `Xfig`): use, modify, sublicense and redistribute freely, as long as the copyright and permission notice stay intact. RustFig may read, port and reuse their code, comments and data tables. [`docs/source-map.md`](../source-map.md) maps every C file to its RustFig module, status and plan task; update it when you port or review a file.
- `docs/source-audit.md` lists every xfig function with its status (S4); `cargo xtask source-audit` regenerates the table (not part of `ci`, skips without `old/`) and keeps the status columns. Update the status of a function when you port or replace it.
- References in `old/` (gitignored, never commit it): the C sources (`old/xfig-3.2.9a/src/`, `old/fig2dev-3.2.9a/fig2dev/`), the format specs (`doc/FORMAT3.2` and older), the HTML manual with screenshots of every panel (`doc/html/`, `doc/html/images/`), `xfig.man.in`, the app defaults (`app-defaults/`), and fig2dev's man pages. Before building UI, look at the manual's image of that panel; compare with the real xfig where it helps.
- Ported code: translate into idiomatic Rust that follows `CLAUDE.md`'s rules (no panics, `Result`, layering) rather than transliterating C. Put a comment at the top of the Rust file (after its `//!` doc) naming the sources, e.g. `// Ported from xfig src/u_draw.c (xfig licence, see LICENSE-xfig).`, and add the file with its sources to the list at the end of `LICENSE-xfig`; copyright holders of the C file not yet listed there go into its notice. Tables, strings and constants copied from xfig count as ported. `cargo xtask licences` (part of `ci`) fails when a file says "Ported from xfig/fig2dev" without pointing to `LICENSE-xfig`, or when the list and the files disagree.
- Some files under `old/` are not under the xfig licence (fig2dev's `lib/` replacement C functions; several figure libraries in `Libraries/` carry their own notice or none). Check the header before reusing; library figures follow the asset rules in [`rules.md`](rules.md).
- Algorithms from papers are fine; cite them in `NOTICE` (X-splines: Blanc & Schlick 1995).
